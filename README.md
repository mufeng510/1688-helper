# 1688 智能助手（1688-helper）

个人自用的 1688 买家侧 Chrome 扩展（Manifest V3）。核心功能：

- **模块 B（完整交付）**：监控指定 1688 商品的全部 SKU 变化（新增/删除/规格属性/库存/价格），定时扫描 + 桌面/Webhook 通知。普通库存数量增减不记录也不通知；默认只发「上架 / 下架 / 售罄 / 补货 / 规格变化 / 低库存预警（跌破阈值，默认 5 件）」，其余场景可全局统一设置，也可每商品单独覆盖（SKU 监控 → 详情 → 通知规则）。
- **模块 A（真实订单已出现，只读适配 v0.5.0）**：揽收超时订单识别与自动理赔——任务框架、状态机、去重、重试、通知已实现并经模拟数据验证；2026-11-15 真实揽收超时订单已出现（另一买家账号），揽收超时入口（hover「待收货」→「揽收超时」）/申请页/结果回读已适配；**2026-11-16 端到端干跑验证通过**（发现 1 笔 → 去重入队 → `needs_human` → 结果回读 `rejected`，重扫不重复入队），**真实提交不启用**（平台当前不受理该单，且已有理赔记录），见 `docs/1688_PAGES.md` §7。
- **模块 D（1688 商品导入工作台，2026-11-15 新增，v0.4.0）**：商品详情页悬浮按钮 → 采集 `window.context`/outerHTML（SW，MAIN world）→ 工作台 ingest 预览 → 确认卡片（名称/区块/主图/详情图可编辑勾选）→ execute 入库；设置页新增「工作台」栏（Base URL + manage Token，存 chrome.storage.local，请求走 SW + 授权源白名单）；v0.4.0 起支持重复导入防护（by-offer 检查 + 更新/新建单选 + 工作台 409 兜底）。详见 `docs/IMPORT_1688.md`。
- **模块 C（预留）**：HTML 采集能力边界已划定，本阶段不实现，等待用户后续增量任务书。

本项目不与妙手等软件集成，不依赖自建服务器，所有数据保存在浏览器本地 IndexedDB。

## 安装（个人自用，开发者模式）

1. 克隆本仓库并构建：
   ```bash
   npm ci
   npm run build     # 产物输出到 dist/
   ```
2. Chrome 打开 `chrome://extensions`，开启右上角「开发者模式」。
3. 点击「加载未打包的扩展程序」，选择本仓库的 `dist` 目录。
4. 出现「1688 智能助手」卡片即安装成功（扩展 ID 由 dist 的绝对路径哈希决定，换目录会变）。

## 使用

### SKU 监控

1. 打开 1688 商品详情页（`detail.1688.com/offer/<id>.html`），点击工具栏扩展图标，弹窗里点「添加监控」。
2. 首次扫描只建立基准快照（不通知）；第二次扫描起对比变化并按策略通知（每商品每轮汇总一条）。
3. 管理页（扩展图标 →「打开管理页」或直接打开 `chrome-extension://<id>/pages/manage/manage.html`）：
   - **总览**：运行状态、待处理理赔、今日成功数、监控商品数、今日 SKU 变化数、最近扫描与异常。
   - **SKU 监控**：商品列表（状态/最近扫描/SKU 数/连续失败）、详情（当前 SKU 快照、历史变化、历史库存）、暂停/恢复/立即扫描/删除。
   - **理赔管理**：订单列表、状态筛选/搜索/时间筛选、失败原因、批次汇总、模拟模式提示。
   - **任务**：队列中/执行中/完成/失败任务，下次执行时间。
   - **系统设置**：SKU 全局扫描间隔、SKU 通知规则（哪些场景通知，桌面+Webhook 共用，可每商品覆盖）、理赔扫描间隔与模式、Webhook、桌面通知开关、日志级别。
   - **数据与备份**：全库导出 JSON 备份、导入恢复（合并/替换）、按天清理历史、重置扩展（危险）。

### 通知

- 桌面通知（默认开启）：SKU 变化汇总、理赔批次结果、异常（登录失效/风控/连续失败暂停等）。SKU 变化默认只通知 上架/下架/售罄/补货/规格变化/低库存（≤5 件，可改）；普通库存数量增减不记录。可在系统设置「SKU 通知规则」或商品详情里自定义。
- Webhook（默认关闭）：在系统设置填 URL/方法/请求头/请求体模板（支持 `{{title}}`/`{{body}}`/`{{text}}` 占位符），先点「授权 Webhook 域名」授予该域名权限，再用「发送测试消息」验证。Webhook 与桌面通知共用「SKU 通知规则」过滤。
- Webhook URL/密钥只存本地 `chrome.storage.local`，不写日志；请求不携带任何环境 Cookie。

### 注意

- 扩展使用你**当前 Chrome 里已登录**的 1688 账号，不独立登录、不碰验证码/风控。
- 扫描在**后台标签页**执行，不占用/刷新/抢焦点；遇到验证码/登录失效会保留标签并通知你人工处理。
- 理赔模式默认「模拟模式」（虚构订单验证框架）；真实订单出现后（v0.5.0），live 模式仅做发现与只读探测——**不会**提交真实理赔（平台当前不受理该单，且已有理赔记录；启用自动提交需单独评审与用户授权；live 端到端干跑已验证，2026-11-16）。

## 已知限制

- **真实理赔提交未启用**：真实订单已出现并完成只读适配（发现/去重/`needs_human` 兜底/结果回读），端到端干跑已验证（2026-11-16）；自动提交成功识别**未验证**——平台当前不受理该单（48h 承诺时间未到 + 已有理赔记录），且任何真实提交需单独评审与用户明确授权。理赔链路日常仍走模拟模式验证框架。
- **真实 SKU 变化对比未观察到**：目前真实数据仅两次扫描（`changes: 0`）；真实变化检测由单测 + 真实页面结构保证，尚未遇到真实库存/价格变化。
- **浏览器重启恢复已验证**：电脑重启后扩展自动恢复调度（SW 启动补建 alarm 并执行到期扫描）；SW 被 Chrome 回收后的恢复有单测覆盖。
- **导入恢复未端到端验证**：导出已验证；导入读取的是同一代码路径但本次未跑通（临时隔离实例被关闭）。
- **Broken image**：监控列表商品图 `og:image` 失效时自动隐藏（onerror），未换图源。
