# 商店审核材料：权限理由、单一用途声明、数据实践声明

适用于 Chrome Web Store（隐私实践 / Privacy practices 表单）与 Edge Add-ons（相同字段）。
所有回答与 `public/manifest.json` v0.5.0 严格一致。

## 1. 单一用途声明（Single purpose）

> 本扩展仅用于辅助 1688 买家管理其已登录账号下的采购工作：监控已添加商品的 SKU 变化并通知、识别并追踪揽收超时订单的理赔任务（只读模式，真实页面已适配并经端到端干跑验证，不提交真实理赔）、将商品详情页数据导入用户自建的工作台服务。不包含任何与此无关的功能，不修改网页内容（仅在商品详情页注入一个「导入」悬浮按钮），不绕过 1688 的登录、验证码或风控机制。

## 2. 权限逐项理由

| 权限 | 用途（审核用语） |
|---|---|
| `storage` | 保存用户配置（扫描间隔、通知开关、Webhook 地址/请求头、工作台地址与 Token 等），数据仅存本机 `chrome.storage.local`。 |
| `alarms` | 定时任务调度（SKU/理赔扫描巡检），避免常驻 Service Worker。 |
| `scripting` | 向用户已打开的 1688 商品详情页注入 SKU 采集脚本；创建后台标签页执行扫描时，向其全部 frame（含 `air.1688.com` 订单列表 iframe）注入采集/只读探测脚本（`air.1688.com`、`bao.1688.com` 等 `*.1688.com` 子域）。仅在 `*.1688.com` 范围内使用。 |
| `notifications` | 通过浏览器桌面通知提醒用户：SKU 变化汇总、理赔批次结果、登录失效/验证码/风控、连续失败暂停等异常。 |
| `host_permissions: *://*.1688.com/*` | 读取 1688 商品详情页与买家订单页中的结构化数据（商品 SKU、订单状态）及「我申请的理赔」列表状态（理赔结果回读），与用户已登录的会话配合使用；不访问其他网站。 |
| `optional_host_permissions: http://*/*`、`https://*/*` | 仅当用户在设置页**主动填写并点击「授权域名」**时才请求对应来源权限，用于：① 向用户自建的 Webhook 推送通知；② 向用户自建的工作台（如 192.0.2.10:8080 或局域网地址）发送商品数据。未授权的域名扩展无法访问；这些域名由用户自己拥有控制。 |
| `content_scripts`（`*://detail.1688.com/offer/*.html`、`*://m.1688.com/offer/*.html`，document_idle） | 仅在商品**详情页**注入一个「📥 导入工作台」悬浮按钮及预览确认卡片；match 模式已精确限制到 offer 详情页路径，不注入其他页面。 |

无远程代码（remote hosted code）：所有 JS 均随扩展打包，不加载、不执行远程脚本。

## 3. 隐私实践表单建议答案（Chrome Web Store / Edge）

收集的数据类型：**不收集任何受管控的用户数据**（no collection of personal/sensitive user data）。
具体声明：

- 不收集位置、浏览历史、个人通讯、身份信息、凭据、支付信息；
- 扩展处理的信息（订单、商品、SKU 快照、配置、Token）全部保存在用户本机（IndexedDB / chrome.storage.local），**开发者不接收、不存储、不出售任何数据**；
- 网络请求仅发往：① `*.1688.com`（读取用户已登录可见的数据）；② 用户自己配置并授权的 Webhook / 工作台地址；
- Webhook/工作台接收到的数据仅对用户自己的服务可见，开发者无法访问；
- 不转让数据给第三方；
- 不出售数据（含用于信用/画像目的的转让）；
- 用户对数据的控制：所有数据可在「管理页 → 数据与备份」导出/清空；清除扩展即删除全部本地数据。

如表单要求提供隐私政策 URL，填：
`https://github.com/mufeng510/1688-helper/blob/main/docs/store/privacy-policy.md`

## 4. 常见审核问题预案

1. **为什么要 host 到 1688.com**：核心功能是在用户已登录的 1688 页面读取 SKU/订单数据，无法通过其他方式实现。
2. **为什么 optional 域名是 `http://*/*` + `https://*/*`**：用户自建工作台可能部署在局域网 `http://<IP>:8080`（内网 IPv4 无法预知），也可能用 HTTPS 公网域名。因此做成可选权限 + 运行时授权；未授权不访问。如需缩窄，可在审核后改为仅 https。
3. **数据是否上传服务器**：否，开发者无服务器。Webhook/工作台是用户自建服务。
4. **是否绕过验证码/风控**：否。检测到风控/验证码时暂停任务、桌面通知、保留标签页等待人工处理。
5. **理赔模块真的在申请理赔吗**：否。模块默认 `claimMode=simulation`（虚构订单）；即使在 live 模式下发现揽收超时订单，执行器也只做只读探测并一律标记「需人工处理」，**不会向 1688 提交任何真实理赔申请**（真实订单上已验证：平台明示暂不受理且该单已有理赔记录；表单就绪场景同样 needs_human，不自动提交）。启用自动提交需单独评审与用户明确授权。
